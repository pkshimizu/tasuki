# Tasuki

要件を Discord に投稿すると、役割ごとのエージェントが仕様作成・タスク分解・デザイン・実装・レビューを進めるソフトウェア開発 AI。

開発中。自動テストでは要件の投稿からマージの知らせまで通っているが、実際の Discord と対象リポジトリでの通し確認はまだ行っていない。

## しくみ

```
人 ──(Discord)──┐                       ┌── 仕様マスター
                 │                       ├── プランナー
GitHub ──────────┼─▶ 監視スレッド ─▶ 司令塔 ─▶ 指示 ─┼── UIデザイナー
                 │      ▲                            ├── プログラマー
エージェントの終了 ┘      └──── 指示の実行 ◀──────────┘── レビュアー
```

- **監視スレッド**（プログラム）は、Discord と GitHub から新しい出来事を集め、司令塔に渡し、司令塔の指示を実行する。次に何をするかは決めない。
- **司令塔**（LLM）は、出来事と今の状況を見て、どのエージェントに何を指示するかを決める。段階の順番や、やり直しの回数は決まっていない。
- **エージェント**は Claude Agent SDK で動き、対象リポジトリの git worktree で作業する。

| 役           | すること                                                                |
| ------------ | ----------------------------------------------------------------------- |
| 仕様マスター | 要件を確かめ、不明点を質問し、仕様を書いて PR を作る                    |
| プランナー   | 仕様の追加・更新を受けて今の Issue を確かめ、Issue を作成・更新する     |
| UIデザイナー | デザインシステムに沿って HTML モックを作り、PR を作る                   |
| プログラマー | Issue に従って実装とテストコードを書き、PR を作る。レビューの指摘を直す |
| レビュアー   | PR を確かめ、指摘を PR にコメントする                                   |

設計の詳しい説明は [docs/DESIGN.md](docs/DESIGN.md)。

## 準備

### この PC

- Node.js 22.13 以上（23 未満）
- git と [GitHub CLI](https://cli.github.com/)。`gh auth login` で、対象リポジトリに書き込めるアカウントにログインしておく
- Windows では Git Bash が必要（Git for Windows に含まれる）。Tasuki は git の場所から `bash.exe` を探してエージェントに使わせる。見つからないときは Windows PowerShell で動かすが、日本語のファイルが文字化けすることがあるので、環境変数 `CLAUDE_CODE_GIT_BASH_PATH` に `bash.exe` の場所を入れる
- Claude Code にログインしておく（エージェントはこの PC の Claude Code のログインで動く）
- 対象リポジトリを clone しておく（`origin` が対象リポジトリを指していること）

```
git clone https://github.com/pkshimizu/tasuki.git
cd tasuki
npm ci
npm run build
npm link   # tasuki コマンドを使えるようにする
```

### Discord

1. サーバーに、要件・質問・お知らせの 3 つのチャンネルを作る。
2. [Discord Developer Portal](https://discord.com/developers/applications) で Bot を作り、**Message Content Intent** を有効にする（投稿の本文を読むために必要）。
3. Bot をサーバーに招待し、3 つのチャンネルで次の権限を与える: チャンネルを見る、メッセージを送信、公開スレッドの作成、スレッドでメッセージを送信、メッセージ履歴を読む。
4. Bot のトークンを、環境変数 `TASUKI_DISCORD_TOKEN` に入れる（設定ファイルには書かない）。
5. チャンネルの ID と、要件を投稿する人のユーザー ID を控える（Discord の開発者モードで、右クリックからコピーできる）。

Tasuki は Discord を PC から読みにいくだけで、外から PC への接続口は作らない。

### 対象リポジトリ

1. `templates/tasuki/config.yaml` を、対象リポジトリの `.tasuki/config.yaml` にコピーして書き換え、既定のブランチに入れる。
2. 既定のブランチを保護する（PR 必須・CI の合格必須）。エージェントが既定のブランチに直接 push するのを GitHub 側でも防ぐため。
3. 依存パッケージの導入など、作業フォルダの準備が要るなら、`workspace.setup` にコマンドを書く。エージェントの作業フォルダ（git worktree）ごとに、初めて用意したときと `workspace.setup_on_change` のファイルが変わったときに Tasuki が実行する。
4. プロダクトの情報を、対象リポジトリの文書として書く（下の「プロダクトの情報」）。

対象リポジトリの `CLAUDE.md` も、エージェントが読む。

### プロダクトの情報

開発対象のプロダクトの背景やルールを、対象リポジトリの文書として管理する。Tasuki はエージェントを起動するたびに、既定のブランチの最新の内容を読み、その役に必要な種類の本文を指示に埋め込む。文書を直す PR がマージされると、次の起動から効く。

| 種類             | 既定の置き場                                                 | 渡す先                                   |
| ---------------- | ------------------------------------------------------------ | ---------------------------------------- |
| コンテキスト     | `docs/CONTEXT.md`                                            | すべてのエージェント                     |
| アーキテクチャ   | `docs/ARCHITECTURE.md`・`docs/architecture/`                 | すべてのエージェント                     |
| 仕様作成ルール   | `docs/rules/spec.md`                                         | 仕様マスター                             |
| 実装ルール       | `docs/rules/implementation.md`・`docs/rules/implementation/` | プログラマー                             |
| レビュー観点     | `docs/review-perspectives.md`・`docs/review-perspectives/`   | レビュアー                               |
| コミットルール   | `docs/rules/commit.md`                                       | 仕様マスター・UIデザイナー・プログラマー |
| タスク作成ルール | `docs/rules/task.md`                                         | プランナー                               |
| プルリクルール   | `docs/rules/pr.md`                                           | 仕様マスター・UIデザイナー・プログラマー |
| マージルール     | `docs/rules/merge.md`                                        | 司令塔                                   |

- 置き場は `.tasuki/config.yaml` の `knowledge` で変えられる。どの種類も、ファイル・フォルダ・その一覧を書ける。フォルダは、中の `.md`（下のフォルダも含む）を名前の順に読む。
- 無い文書は読み飛ばす。必要な種類だけ書けばよい。
- 本文はそのまま指示に入るので、長すぎる文書はそのぶん利用枠を使う。
- `tasuki check` で、種類ごとに見つかった文書を確かめられる。
- 司令塔への進め方の方針（同時に動かしてよい役など）は、コンテキストに書く。

## 動かし方

```
tasuki check [フォルダ]   設定を点検する
tasuki start [フォルダ]   常駐して開発を進める
```

- フォルダは対象リポジトリの clone（省略すると今のフォルダ）。
- `tasuki start` は `poll_interval`（既定 60 秒）ごとに Discord と GitHub を確かめる。
- 初めて起動したときは、その時点の投稿・PR・Issue を出来事にせず、それ以降に変わったことから扱う。
- Ctrl+C を 1 回押すと、新しい指示を出すのをやめ、動いているエージェントの終了を待って止まる。もう 1 回押すと、エージェントを中断して止まる。
- 止めて再開しても続きから進む。途中で止まった実行は、再開したときに司令塔に伝わる。

## 使い方

### 要件を伝える

要件チャンネルに、要件を簡潔な文で投稿する。投稿 1 つが要件 1 件になる。

### 質問に答える

仕様の作成中や実装中に、人にしか決められないことが出てくると、質問チャンネルにスレッドができる。そのスレッドに返信すると、続きが進む。

### マージ

`merge` の設定で、工程（仕様・デザイン・実装）ごとに選ぶ。

- `human`（既定）: お知らせチャンネルに PR の作成が届くので、GitHub でレビューしてマージする。PR にコメントを書くと、指摘として扱われる。
- `auto`: 司令塔がマージしてよいと判断し、CI がすべて合格していれば、Tasuki がマージする。

PR がどの工程かは、変えたファイルの置き場で決まる。仕様の置き場（`paths.specs`）だけなら仕様、デザインの置き場（`paths.design`・`paths.design_system`）だけならデザイン、それ以外は実装。

## プログラムで必ず守ること

司令塔やエージェントの判断に任せないのは、次の 3 つだけ。

1. **CI 合格がマージの条件**: Tasuki がマージするのは、設定が `auto` で、PR の CI がすべて合格しているときだけ。
2. **許可した人の投稿だけ読む**: Discord は設定したチャンネルと、`allowed_users` の投稿だけを扱う。
3. **危険な操作の拒否**: 既定のブランチへの直接 push、force push、リモートのブランチの削除、PR のマージ、`.tasuki/` の書き換え、作業フォルダの外への書き込みを、実行時に拒否する。それ以外の操作は広く許可する。

シェルのコマンドは文字列で判定するので、すり抜けを完全には防げない。既定のブランチは GitHub 側の保護でも守ること。

## 記録の場所

- 記録（出来事・質問スレッド・エージェントの実行・司令塔の判断）: `~/.tasuki/state/<owner>__<repo>.db`
- 作業フォルダ（git worktree）: `~/.tasuki/worktrees/<owner>__<repo>/`

## 利用上限

エージェントは Claude Code のログイン（定額プラン）の利用枠で動く。利用上限に達すると、回復時刻まで新しいエージェントを起動せず、回復したあと司令塔がやり直すかを決める。
